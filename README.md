# Тестирование веб-приложения — API + UI автотесты

🧑‍💻 [Моё резюме на GitHub](https://github.com/Aleynikov93)

## 📋 О проекте

Учебный проект по автоматизации тестирования веб-приложения с использованием Python и PyTest. Цель — отработать навыки написания автотестов для API и UI, выстроить структуру тестового проекта, научиться фиксировать результаты и логи тестирования.

Проект выполнен в рамках курса [«Тестирование ПО: Автоматизация и Программирование. Python. API»](https://stepik.org/course/127716/syllabus).

---

## 🧪 Этапы

### Этап 1: Подготовительный ✅

1. Определение объекта тестирования и области покрытия
2. Настройка окружения (Python, PyTest, зависимости)
3. Проектирование структуры тестового проекта

### Этап 2: Написание автотестов ✅

4. Разработка тестов в папке `test/`
5. Реализация вспомогательных утилит в `utils/`
6. Запуск тестов и сбор результатов в `test_results/`
7. Ведение логов выполнения в `logs/`

### Этап 3: Анализ результатов 🔄 *(в процессе)*

8. Анализ упавших тестов и баг-репорты
9. Итоговый отчёт о покрытии
10. Ретроспектива

## 📁 Структура проекта

```
Appproject/
├── test/              # Тест-кейсы (PyTest)
├── test_results/      # Результаты выполнения тестов
├── utils/             # Вспомогательные функции и хелперы
└── logs/              # Логи запусков
```

---

## 🚀 Как запустить

1. Клонируй репозиторий:
```bash
git clone https://github.com/Aleynikov93/Appproject.git
cd Appproject
```

2. Установи зависимости:
```bash
pip install -r requirements.txt
```

3. Запусти тесты:
```bash
pytest test/ -v
```

4. Результаты появятся в папке `test_results/`.

## 🎞️ Ретроспектива

### 🎯 Что получилось хорошо (Keep Doing)

- Чёткое разделение на модули: тесты, утилиты, логи, результаты
- Использование PyTest — мощный инструмент с понятным синтаксисом
- Запись логов помогает быстро локализовать проблему

### 🔧 Что можно улучшить (Start Doing)

- Добавить `conftest.py` с фикстурами для переиспользования кода
- Внедрить параметризацию тестов через `@pytest.mark.parametrize`
- Добавить генерацию HTML-отчётов через `pytest-html`
- Покрыть тесты позитивными и негативными сценариями

### 🛑 Что стоит изменить (Stop Doing)

- Не запускать тесты без предварительной проверки окружения
- Не оставлять хардкод данных прямо в тестах — выносить в конфиги или `.env`

### 🌟 Главный вывод

Автоматизация тестирования требует дисциплины в структуре кода не меньше, чем в ручном тестировании — чистый, читаемый и воспроизводимый тест ценнее, чем быстро написанный но нечитаемый.
